# 2026-08-22 npm Production Dependency Audit

## Result

`npm audit --omit=dev` reports three high-severity entries and no critical entries. The three entries are one transitive chain rather than three independent flaws:

```text
mailparser@3.9.15
└─ html-to-text@10.0.0
   └─ deepmerge-ts@7.1.5
```

The root advisory is [GHSA-ggr8-5vv4-36mx](https://github.com/advisories/GHSA-ggr8-5vv4-36mx). `deepmerge-ts` versions below 8.0.0 can exhaust the stack when both objects supplied to a merge contain recursive references at the same property path. The advisory explicitly states that plain JSON alone cannot create the required recursive object graph.

## Reachability Review

The current application calls `simpleParser(message.source)` in:

- `src/services/aftersalesMailService.js`
- `src/services/erpMailReplyMatcher.js`

`message.source` is an untrusted email Buffer/String. `mailparser@3.9.15` passes the decoded HTML string to `htmlToText(node.textContent)` without application-controlled conversion options. The vulnerable merge is used to compose the library's static defaults with its options object; the external email body is not supplied as a merge operand. Therefore the recursive-object precondition is not reachable through the currently inspected email parsing path.

This conclusion must be revisited if application code begins passing dynamic objects into `simpleParser` options, calls `html-to-text` directly with externally derived options, or uses `deepmerge-ts` directly.

## Remediation Decision

No dependency change is applied in this review:

- npm proposes downgrading `mailparser` to 3.9.8, which replaces `html-to-text@10` with version 9.0.5 and also downgrades several mail dependencies. That is not a supported forward security update.
- Forcing `deepmerge-ts@8` through an npm override would cross the major-version range declared by `html-to-text@10.0.0`. Upstream has not published a compatible package release selecting the patched major, so an override would transfer compatibility risk into this application.

Re-run `npm audit --omit=dev` and inspect the resolved dependency tree before the next deployment. Adopt the first supported `html-to-text` or `mailparser` release that selects `deepmerge-ts >= 8.0.0`, then run the mail service tests and the full suite before deployment.
