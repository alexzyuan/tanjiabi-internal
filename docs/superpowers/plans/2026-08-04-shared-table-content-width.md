# Shared Table Content Width Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task with review checkpoints.

**Goal:** Make managed BI tables size to their resolved column widths, while preserving wide/matrix minimums and wrapper-owned horizontal scrolling.

**Architecture:** Keep width ownership in the shared table manager. Add one internal resolver that sums managed `colgroup` widths, applies the table variant minimum, writes `--tj-table-resolved-width`, and is called after smart sizing and user resizing. Change only the shared table CSS so feature pages inherit the behavior.

**Tech Stack:** Native ES modules, Node `node:test`, layered CSS generated by `scripts/build-styles.js`, Playwright/browser smoke verification.

### Task 2: Implement shared resolved-width calculation

**Files:**
- Modify: `assets/js/data-table-manager.js`

- [ ] **Step 1: Add the internal variant minimum helper**

Add a helper near `classifyDataTableVariant`:

```js
function tableVariantMinimumWidth(table) {
  const variant = table?.classList?.contains?.("data-table--matrix")
    ? "matrix"
    : table?.classList?.contains?.("data-table--wide")
      ? "wide"
      : "standard";
  return variant === "matrix" ? 2400 : variant === "wide" ? 1280 : 0;
}
```

- [ ] **Step 2: Add the single width resolver**

Add `resolveTableWidth(table, { log = false } = {})` after `getTableWrap` or beside the other table sizing helpers. It must read `:scope > colgroup > col`, parse each `style.width`, throw an error if any managed column has no positive finite width, sum widths, apply the variant minimum, set `--tj-table-resolved-width` to `${resolvedWidth}px`, and optionally emit:

```js
console.debug("[data-table-manager] resolved table width", {
  tableKey: table.dataset.tableKey || table.id || "",
  columnCount: columns.length,
  minimumWidth,
  resolvedWidth,
});
```

Use the existing `smartWidthDebugEnabled(table, storage)` gate at call sites so normal logs stay quiet.

- [ ] **Step 3: Call the resolver after smart sizing**

In `applySmartColumnWidths`, replace the direct `totalWidth` CSS-variable write with `resolveTableWidth(table, { log: smartWidthDebugEnabled(table, storage) })`. Keep the returned details and existing signature behavior unchanged.

- [ ] **Step 4: Call the resolver after manual resize**

In `setColumnWidth`, call `resolveTableWidth(table)` after assigning the resized column. This keeps the table width synchronized while the pointer moves.

- [ ] **Step 5: Call the resolver after restore and before scroll hints**

In `restoreSmartWidths`, invoke `resolveTableWidth(table)` after `applySmartColumnWidths` and before `updateStickyOffsets`/`updateScrollHint`; this is defensive and keeps the restore path explicit.
