# 销售复盘明细可售天数设计

## 目标

在销售复盘 MSKU 明细中增加“可售天数”列，展示销售预估板块已经计算并缓存的 FBA 可售天数，不新增接口请求或第二套计算公式。

## 数据口径

- 唯一数据源是 `sales-forecast-dashboard-cache.json` 中每行的 `fbaAvailableDays`。
- 销售复盘与销售预估按 `SID + MSKU` 精确匹配；不得跨店铺按 MSKU 汇总，避免混用不同店铺的库存与日销。
- 缓存不存在、行未命中或可售天数不是有限数值时，前端显示 `—`，不得用 `0` 代替。
- 可售天数保持销售预估的既有含义与数值精度；销售复盘不重新计算库存或日销。

## 结构与归属

- `src/services/salesForecastService.js` 新增只读的 `SID + MSKU → fbaAvailableDays` 缓存索引，不改变销售预估接口返回数据。
- `src/services/dashboardService.js` 在销售复盘仪表盘完成现有明细映射后，调用该索引补齐 `detailRows[].fbaAvailableDays`，并记录缓存命中、匹配数量、缺失数量与缓存更新时间。
- `src/services/lingxingDashboardMapper.js` 为明细行保留匹配必需的 `sid`，并声明 `fbaAvailableDays` 的初始未提供状态；不承担缓存读取。
- `index.html` 在 `FBA库存` 与 `销量达成率` 之间增加稳定列键 `fba-available-days`，显示名为“可售天数”。
- `assets/js/features/sales-dashboard.js` 将有限数值格式化为天数；未提供值渲染 `—`。
- `app.js`、路由和销售预估的计算公式不修改。

## 可观测性与错误

- 复盘响应的 `meta` 增加可售天数缓存来源、更新时间、匹配数量和缺失数量，便于页面状态和日志追溯。
- 缓存读取/结构错误必须记录上下文后向上抛出；不能把读取错误伪装为普通未匹配。
- 合法的空缓存是可观测的未命中状态，页面显示 `—` 并带有明确状态文本。

## 展示与交互

- 列固定置于 `FBA库存` 后、`销量达成率` 前，数值单位为“天”。
- 该列只读，保留现有表格排序、宽度管理和窄屏横向滚动机制。

## 验证

- 服务测试覆盖同店铺匹配、同 MSKU 跨店铺不串值、空缓存、缓存结构错误和响应元数据。
- 前端结构测试覆盖列顺序、稳定列键和 `—` 渲染。
- 浏览器在桌面与窄屏检查新列的文字、表内横向滚动、无页面级溢出和控制台错误。
