# 店铺经营月报项目行配置设计

## 目标

店铺经营月报新增“列配置”入口，用于控制项目明细行的显示与隐藏。虽然入口沿用“列配置”名称，配置对象是项目行，例如广告费、采购成本、软件费用，不是表格的实际完成值、占比、预算值、达成率列。

配置按当前登录 BI 账号保存到服务端。同一账号在不同浏览器或设备登录后，应得到相同的项目行显示偏好。

## 范围与非范围

范围：

- 月报工具栏新增“列配置”按钮，打开项目行配置弹窗。
- 弹窗按 `平台收入`、`平台支出`、`商品成本支出`、`自定义费用`、`利润` 分组展示可配置项目。
- 搜索项目名，支持全选、清空、分组全选/取消和恢复默认。
- 点击“应用”后，立即更新已加载报表的明细行，并持久化当前账号的偏好。
- 固定显示 `上级`、`名称` 两列和所有一级分类小计行。

非范围：

- 不改变动态数据列、预算数据、导出字段或月报 API 请求。
- 不新增管理员统一模板、跨账号共享配置或权限管理。
- 不持久化一级分类的临时展开/折叠状态。

## 用户体验

### 弹窗

入口放在店铺经营月报的现有操作区，靠近导出 Excel 与预算目标操作。弹窗使用现有通用 modal 机械与 Spectrum 风格令牌，包含：

- 可访问的标题、关闭按钮和搜索输入框。
- 顶部“全选全部”“清空全部”“恢复默认”操作。
- 以一级分类分组的原生复选框；每组支持全选和取消。
- 取消和应用按钮；Escape、关闭按钮与遮罩关闭均丢弃未应用的草稿。

“恢复默认”将草稿恢复为全部可配置项目可见，仍需点击“应用”才保存。搜索仅过滤弹窗内项目，不改变已应用设置。

### 表格

一级分类小计行始终保留，因此隐藏该分类下所有明细时，用户仍能看到分类及其汇总。现有展开/折叠交互继续生效；处于展开状态时，渲染器仅输出同时满足“该分类已展开”和“该项目可见”的明细行。

首次没有账号设置时，默认全部项目行可见。保存后刷新页面、重新登录、换浏览器或换设备都会读取同一账号配置。

## 数据模型与归属

服务端在 `data-cache` 下维护一个原子写入的 JSON 存储。顶层以规范化的登录账号标识为 key，每个账号记录版本、隐藏项目的稳定 ID 与更新时间。例如：

```json
{
  "version": 1,
  "users": {
    "finance01": {
      "hiddenMetricIds": ["platform-expense.ad-fee", "custom-expense.software-fee"],
      "updatedAt": "2026-08-06T12:00:00.000Z"
    }
  }
}
```

项目 ID 使用 `storeOperatingMonthlyReportMapper` 所定义指标的稳定标识，绝不使用中文展示名作为持久化 key。读取时会只接受当前指标定义中的 ID，自动忽略历史或未知 ID，防止旧设置破坏渲染。

账号身份只由服务端 `req.user` 确定，客户端请求不包含、也不允许指定账号名。账号标识优先使用认证用户的 `username`，没有时采用认证服务已提供的稳定身份字段；若认证启用但身份缺失，接口返回明确错误而不是写入共享默认设置。

## 接口与所有权

新增两个需要登录态的同一路由：

- `GET /api/store-operating-monthly-report/row-visibility`：返回当前账号的 `hiddenMetricIds` 和保存时间。
- `PUT /api/store-operating-monthly-report/row-visibility`：只接收 `hiddenMetricIds` 数组，验证为字符串数组并过滤为当前已知指标 ID，原子写入当前账号记录后返回规范化结果。

所有请求沿用现有会话认证与错误响应。读取或写入数据存储异常必须返回非 2xx 错误并留下可定位日志；前端不回退到 `localStorage`，也不假装保存成功。

后端存储与校验归 `src/services/storeOperatingMonthlyReportRowVisibilityService.js` 所有，使用 `src/utils/jsonStore.js` 的恢复读取与原子写入能力。`server.js` 仅注册路由、注入当前会话用户并转换 HTTP 输入/输出。

前端状态、加载、弹窗事件和渲染过滤归 `assets/js/features/store-operating-monthly-report.js` 所有；`app.js` 只继续负责创建 feature 和注入现有通用 modal 工具。HTML 结构保留在 `index.html`，样式只修改 `assets/css/pages/56-store-operating-monthly-report.css` 与已有共享 modal 源样式必要的扩展，随后运行 `npm run build:css` 生成 `styles.css`。不修改月报 mapper 的业务分类、数据加载服务、导出映射或共享表格宽度管理器。

## 状态与错误处理

页面加载月报视图时并行读取账号配置；首次报表渲染可使用默认全显示，配置读取完成后再按返回设置重渲染当前表格。配置读取失败必须在月报状态区显示“项目行配置读取失败”，保留全部行可见，且不得将失败写成本地缓存。

弹窗维护独立草稿。保存请求进行期间禁用应用按钮；成功后将草稿提交为已生效状态并重新渲染现有数据。保存失败时显示具体错误、保留弹窗草稿和先前已生效的表格状态，允许用户重试。未加载报表数据时，配置仍可保存；下一次数据渲染应应用它。

## 测试与验证

后端单元测试覆盖：

- 两个账号配置隔离，且更新不会覆盖另一账号。
- 未知、重复和非法 ID 的规范化处理。
- 缺失认证身份和 JSON 存储读写失败的明确错误。

前端特征测试覆盖：

- 展开分类时，隐藏项目不渲染，一级小计仍渲染。
- 弹窗草稿的搜索、分组操作、取消、恢复默认与应用。
- 读取配置成功后的初始应用，以及保存失败后不改变已生效表格状态。

集成验证覆盖：已登录用户请求只能读写自己的配置，接口请求不携带用户身份字段；桌面与窄视图截图确认弹窗、焦点、键盘关闭和表格横向滚动没有回归；浏览器网络检查确认 GET/PUT 请求与保存结果一致。
