# 滞销处置周报设计

**日期：** 2026-07-31  
**状态：** 已与用户确认，等待规格审阅后进入实现计划  
**范围：** 替换「销售 → 动销预警」现有清货计算器，提供 FBA 滞销处置周报、日常预警和最近六个月历史周报。

## 1. 目标与边界

该功能服务于成熟跨境电商的库存现金流管理。它识别高库龄、低转化、持续亏损或仍在亏损投放的 FBA SKU，按现金风险金额排序，并给出只读的处置建议。

功能不自动修改商品价格、不创建亚马逊移除/清算任务、不暂停广告、不发送钉钉或导出 Excel。Codex MCP 仅用于开发阶段验证领星数据可得性；运行时只使用 BI 既有的领星 API 适配层。

旧页面的「近 30 日均毛利为负且库存大于 10」清货计算器被完全替换。旧前端功能和无其他调用方的旧接口会在实现时移除，避免两套冲突规则共存。

## 2. 页面与交互

入口保持为「销售 → 动销预警」，原 `view-clearance` 替换为新页面：

1. **滞销处置周报**（默认）：展示最近成功生成的周报快照。
2. **日常预警**：按相同规则读取实时数据，供运营日常查看；不覆盖任何周报快照。
3. **历史周报**：按报告周选择已生成快照，保留六个月。

页面为表格优先的管理视图：顶部为报告周期、生成状态、数据截至日和筛选；随后为高风险 SKU 数、90 天以上库存数量、90 天以上库存金额、近 30 日亏损毛利等 KPI；最后为按资金风险金额降序的表格。默认范围为全部站点和全部店铺，支持国家、店铺、运营、风险等级筛选。

表格每行以「店铺 / 站点 / MSKU」为一条业务记录，并至少包含：

- 风险等级；店铺/站点；MSKU；
- 当前 FBA 可售数量、90 天以上数量；当前库存金额、90 天以上库存金额；
- 可售天数、30 日库存现金转化率；
- 30 日销量、30 日毛利、30 日平均毛利；
- 30 日广告花费、广告 ACOS；
- 资金风险金额；
- 清仓回收、清算回收、移除费状态；
- 主处置建议和触发原因。

窄屏下仅表格容器横向滚动；页面、应用外壳和筛选区保持在视口宽度内。标签使用语义化按钮，支持键盘操作和明显的 `:focus-visible` 状态。

## 3. 数据口径与规则

### 3.1 时间、范围和货币

- 每周二 09:00（`Asia/Shanghai`）生成一次。
- 周报使用截至**上周日**的连续 30 个自然日；上周日为含端点，开始日为截至日向前推 29 天。这样避免周一的订单、广告和退款尚未完整同步。
- 范围为全店 FBA 库存。前台可按国家、店铺、运营筛选。
- 页面同时展示店铺原币的处置情景金额和 BI 统一币种的排序金额。不得将不同原币直接相加；统一币种转换沿用项目现有领星汇率/金额口径，并在快照中保存转换结果与其口径元数据。

### 3.2 核心指标

- `30 日库存现金转化率 = 近 30 日销量 ÷ (近 30 日销量 + 当前 FBA 可售库存)`。
- 该指标不命名为亚马逊官方售罄率，避免与按平均库存计算的 Amazon sell-through 混淆。
- `30 日平均毛利 = 30 日毛利 ÷ 30 日销量`；销量为零时显示「无销量」，不除零也不伪造数值。
- `广告占比 = 30日广告花费 ÷ 30日总销售额`。总销售额大于零时，广告浪费信号为「30 日毛利为负、广告花费大于零且广告占比 ≥15%」；总销售额为零但仍有广告花费时，也直接标记为广告浪费。ACOS 仅在广告销售额大于零时计算，否则显示不可用。
- `资金风险金额 = 90天以上库存成本 + 未来3个月仓储费 + 未来3个月资金占用成本 + max(0, -30日毛利)`。
- 资金占用成本默认使用年化 12%，作为页面可见且可调整的经营参数。快照保存生成时实际使用的参数，历史报告不可被新参数改写。

### 3.3 风险等级

风险等级按以下顺序判定，满足更高等级时不再降级：

| 等级 | 条件 | 业务含义 |
| --- | --- | --- |
| 强制处置 | `(库龄 ≥181天 或 可售天数 >180天) 且 30日库存现金转化率 <10% 且 30日毛利 ≤0` | 默认停投、停止补货，比较清仓、清算与移除 |
| 高风险 | `库龄 ≥90天 且 可售天数 >120天 且 30日库存现金转化率 <15%` | 必须进入周报并形成处置建议 |
| 关注 | `库龄 ≥90天 且 可售天数 >90天 且 30日库存现金转化率 <20%` | 停止补货并观察价格、广告与销量 |
| 正常 | 不满足上述条件 | 不进入默认高风险表格，可在日常预警筛选查看 |

“库龄”取 FBA 90 天以上库存数量是否大于零，以及 181 天以上库存数量是否大于零；不会把整个 SKU 的当前库存误当成高库龄库存。

### 3.4 处置情景

处置情景都基于该行的 90 天以上库存数量，而不是整个可售库存：

- **清仓回收（内部情景）**：`90天以上数量 × 9.9 原币`。
- **清算回收（内部保守情景）**：`90天以上数量 × 1 原币`。它是用户指定的经营比较值，页面不能把它描述为亚马逊承诺的实际回款。
- **移除 FBA**：不声称会立即回收现金。只有同时具备站点、尺寸分段和重量并得到适用费率时，才计算移除费及「移除费与未来仓储/资金占用节省」的净效果。

领星源数据若缺少尺寸分段或重量，移除费字段必须显示「缺少尺寸/重量，无法计算」，并附带可追溯缺字段原因。不得用固定移除费、猜测尺寸或静默回退值代替真实费用。

每条记录只输出一个主建议：停投观察、降价清仓、捆绑促销、申请清算或移除 FBA。建议与触发的库龄、转化、毛利、广告占比/ACOS 和资金风险原因一起展示。

## 4. 架构与文件归属

### 后端

- `src/services/slowMovingRiskService.js`：拉取和组合库存、近 30 日经营、广告数据；计算指标、等级、排序和建议。该服务是业务规则的唯一来源，并接收适配器/时间/参数依赖，便于测试。
- `src/services/slowMovingRiskSnapshotStore.js`：基于项目 JSON 存储工具写入、读取和按六个月策略清理快照。快照包含报告键、生成状态、数据截至日、参数、汇率元数据、KPI、行数据和可观测性摘要。
- `src/jobs/slowMovingRiskWeeklyJob.js`：实现周二 09:00 的时区判断、周键幂等保护、一次生成和失败状态记录。复用项目已有的持久化状态与调度模式，不引入额外 cron 依赖。
- `routes/inventory.js`：提供实时预警、周报列表和指定周报读取 API。路由仅校验请求、调用服务和返回错误，不承载规则。
- `server.js`：仅装配依赖、挂载路由、启动调度器；不新增业务状态机或渲染逻辑。
- 现有领星适配器：按既有职责补足所需 FBA 库龄、库存金额、可售库存、销售/毛利与广告字段；字段翻译留在相应 mapper 中，不散落在路由或页面。

推荐 API 边界：

- `GET /api/dashboard/slow-moving-risk/live`：按前台筛选读取实时预警；
- `GET /api/dashboard/slow-moving-risk/reports`：读取六个月内的报告目录和生成状态；
- `GET /api/dashboard/slow-moving-risk/reports/:reportKey`：读取一个不可变历史快照。

### 前端

- `index.html`：保留导航入口，替换 `view-clearance` 标记为三标签页、筛选、KPI 和语义化表格。
- `assets/js/features/slow-moving-risk.js`：拥有页面状态、请求、筛选、标签交互、表格渲染和错误展示。
- `app.js`：仅导入并装配新特性，移除旧 `clearance-calculator` 的装配。
- `assets/css/pages/*`：新增或扩展本页样式源文件，使用 `design.md` 的现有语义 token 和共享表格/筛选规则。随后运行 `npm run build:css` 生成唯一 CSS 产物；不得手改 `styles.css`。

不会将新业务状态、渲染器或事件绑定块塞回 `app.js`，也不会修改无关的销售、利润、广告、售后或 FBA 物流页面。

## 5. 生成、留存和可观测性

周报通过报告键（截至上周日）保证幂等：同一报告键已有成功快照时，定时器重启或重复轮询不得重算或覆盖。历史保留六个月，清理时只删除明确早于保留边界的快照和关联状态。

最近成功快照是默认周报页的数据来源。无快照时，用户可以查看实时预览，但 UI 必须明确标记为「实时预览，未保存为定时周报」。

核心数据源任一失败时，本次生成状态为失败，保存数据源名称、筛选/日期参数摘要、开始/结束时间、行数、缓存命中信息和错误摘要；不保存半成品，也不得以旧快照冒充本周新报告。只有 SKU 级移除费字段缺失时允许该行部分可用，且需明确缺失原因。

日志不得包含令牌、密码或完整敏感响应。页面展示报告生成时间、数据截至日、快照状态和数据源状态，使问题可追溯。

## 6. 验证与测试

新增测试覆盖：

1. 三层阈值和优先级；30 日转化率；零销量；毛利与平均毛利；广告占比 ≥15% 的广告浪费、零销售但仍有广告花费；资金风险排序；原币清仓和清算情景。
2. 移除费所需字段缺失时的明确不可计算状态，且不存在虚构费率。
3. 快照读取、六个月清理、同周重复执行保护、时区与截至上周日的日期窗口。
4. 路由的筛选参数、成功/失败返回以及指定历史快照读取。
5. 旧清货计算器没有残留装配和前台入口。

完成实现前运行项目现有 JS/CSS 检查和相关测试。浏览器验证需覆盖桌面和窄屏：页面无控制台错误；鼠标和键盘均可切换标签与筛选；表格仅自身横向滚动；请求参数、数据截至日、快照状态与 UI 显示一致。

## 7. 非目标与后续扩展

本期不实现真正的亚马逊移除/清算下单、广告暂停、商品改价、消息通知或报表导出。若后续接入可靠的亚马逊尺寸/重量与费率数据，才可在现有移除费边界内增加准确费率计算；不得通过硬编码通用费率抢先实现。
