# 店铺经营月报按店铺展示设计

## 目标

让月报表头准确反映店铺筛选范围：选择店铺时逐店铺展示四项指标，未选择店铺时展示所有店铺总计。国家筛选继续决定人民币汇总或单国家原币展示，预算值继续从现有月度预算目标联动读取，实际完成值继续来自领星订单利润 API。

## 用户界面

- 左侧固定两列：`分类`、`名称`。
- 每个报表分组占四列：`实际完成值`、`占比`、`预算值`、`达成率`。
- 有店铺筛选时，分组标题使用选中的店铺名称。
- 无店铺筛选时，只生成一个 `全部店铺` 分组，数据为筛选国家范围内所有店铺的合计。
- 单国家原币模式下，如果一个店铺出现多个币种，分组标题追加币种，例如 `店铺A · USD`；跨国家时各店铺分组统一使用 `CNY`。
- 月份变化仍自动刷新；国家/店铺变化仍先修改筛选，再由查询按钮刷新。

## 数据与服务边界

- 领星订单利润记录先按 `storeName` 和 `currencyCode` 分组。
- 有店铺筛选时保留每个选中店铺；无店铺筛选时使用稳定的 `全部店铺` 聚合分组。
- 预算行使用同一店铺/国家范围分组，并在 CNY 模式下按该店铺/国家的领星汇率转换后汇总；原币模式按店铺和币种匹配预算。
- 每个分组仍使用 `buildStoreOperatingReportRows` 生成相同的科目树，前端按 `row.key` 横向合并这些分组。
- 日志保留请求范围、筛选数量、分组数量、币种模式和不可用科目，错误继续抛出，不添加静默兜底。

## 导出

Excel 第一行采用与网页一致的二维表：`分类`、`名称` 后按分组重复四项指标；报表说明保留原筛选范围、币种模式、预算状态和生成时间。导出继续调用同一份月报服务结果，避免网页和导出计算分叉。

## 交互与排序

动态叶子表头使用稳定的 `data-column-key`。月报排序按照被点击分组的具体指标，对分类块整体排序，保持分类与子科目相邻；没有可排序的分类时不改变 DOM。折叠状态按“分组 + 分类”保存。

## 验证

- 服务测试：多店铺 CNY 分组、单店铺原币多币种、全部店铺总计、预算按店铺匹配。
- 前端测试：两级表头、全部店铺默认标题、店铺/币种列值横向渲染、空数据列数。
- 导出测试：动态表头与指标列顺序、分组标题和元数据。
- `npm run check`、`npm test`，以及桌面/窄屏浏览器检查表头、横向滚动、筛选刷新和控制台错误。
