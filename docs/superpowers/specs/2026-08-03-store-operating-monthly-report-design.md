# 店铺经营月报设计

**日期：** 2026-08-03  
**状态：** 已与用户确认，等待规格审阅后进入实现计划  
**范围：** 在「财务」下新增“店铺经营月报”，以领星订单利润为实际值、既有月度预算目标为预算值，提供按月区间、店铺和国家筛选的经营损益表。

## 1. 目标与范围

“店铺经营月报”用于财务和经营复盘，按用户选择的连续月份汇总店铺经营收入、成本、费用和利润，并把已导入的预算目标与实际完成值放在同一张科目矩阵中。

本期包含：

- 「财务 → 店铺经营月报」入口及财务权限控制；
- 开始月份、结束月份、店铺、国家筛选；
- 最长 12 个自然月的跨月累计；
- 领星订单利润实际值、既有预算目标预算值、占比和达成率；
- 单国原币分币种展示、多国人民币汇总；
- 与“销售 → 预算目标”页面的筛选联动和跳转；
- 当前结果导出、数据状态和可观测性。

本期不新建预算维护入口、不新增 BU/平台/区域筛选、不新增图表、不手工录入实际数，也不以模拟或推算数据填补领星未提供的科目。

## 2. 页面与交互

### 2.1 页面结构

页面位于财务导航组，标题为“店铺经营月报”。顶部模块 banner 展示当前统计区间、店铺/国家范围、币种模式和数据更新时间；右侧提供“导出 Excel”与“查看预算目标”动作。

筛选栏包含：

| 筛选 | 规则 |
| --- | --- |
| 开始月份 | `type=month`；默认当前月。 |
| 结束月份 | `type=month`；默认当前月；不能早于开始月份。 |
| 店铺 | 可搜索多选；未选表示全部店铺。 |
| 国家 | 可搜索多选；未选表示全部国家。 |
| 查询 / 重置 | 店铺、国家变化后由“查询”提交；“重置”恢复当前月、全部店铺、全部国家。 |

月份选择完成且范围有效时自动刷新：开始月或结束月变化后，只要两端存在、顺序正确且跨度不超过 12 个月，立即请求新报表。无效范围在筛选栏中给出明确原因，且不会发起请求。国家只收窄店铺候选，不自动移除已选店铺；若已选店铺不属于新国家范围，界面显示可读提示。

筛选状态写入 URL，链接可用于复盘。导出只针对最近一次成功查询的同一份结果，不能导出正在加载、失败或已被筛选修改但尚未查询的数据。

### 2.2 主表

主报表是可展开的损益矩阵，表头标注当前范围，例如“全公司 · 2026-01 至 2026-07 · 人民币汇总”。列为：

| 上级 | 名称 | 实际完成值 | 占比 | 预算值 | 达成率 |
| --- | --- | ---: | ---: | ---: | ---: |

科目树严格按已确认的领星订单利润字段顺序维护，基础信息下只有“店铺/国家”，业务一级项目固定为“平台收入”“平台支出”“商品成本支出”“自定义费用”“利润”。完整字段清单及显示名称唯一维护在 `src/services/storeOperatingMonthlyReportMapper.js`：平台收入包含销量、平均日销、多渠道销量、广告销售额、广告销量、销售额、净销售额、买家运费、促销折扣、退款金额、退货量、退款量、退货率、退款率、FBA库存赔偿、其它收入；平台支出包含平台费、FBA发货费、其他订单费用、仓储费、广告费、推广费、FBA国际物流运费、入库配置费、调整费、平台其它费；领星 API 已返回的费率/占比不再作为重复明细行，表格通用“占比”列仍保留；商品成本支出包含采购成本、头程成本、其它成本；自定义费用包含站外推广费、办公费用、办公费用-租金、认证检测费、办公用品、店铺保险费、软件费用、产品外观设计费、产品平面设计费、服务商费用、办公费用-快递费、办公费用-水电费、信用卡广告费、办公费用-店铺通讯费、样品费、送测佣金（刷单）、差旅费、员工福利费；利润包含毛利润、毛利率、净毛利率。

一级分类可展开/收起，默认折叠明细；利润结果行使用项目现有的低饱和强调底色。上级和名称列、表头固定；只有表格容器允许横向滚动。金额右对齐、使用千分位和等宽数字；百分比有文字说明和语义状态，不能只靠颜色表达。

## 3. 数据口径

### 3.1 时间和实际数据

- 实际完成值唯一取自领星“订单利润” API。服务按选中的每个自然月构建左闭右开日期范围，并统一通过 `src/utils/lingxingDateRange.js` 生成领星参数；前台显示的结束月份保持用户真实选择。
- 服务在后端合并月结果，再按店铺、国家和科目聚合。前端不自行累计订单明细，也不调用领星。
- 科目字段映射集中在专用 mapper 中。一个科目只有在订单利润 API 有明确字段来源时才产生金额；未映射或源字段缺失时显示 `—` 与可追溯的数据状态，不能用 0、其他科目或模拟值代替。只有 API 明确返回 0 时显示 0。
- 销售收入作为 100% 基准。费率、退货率、退款率、毛利率和净毛利率均在销售收入或销量可用且非零时计算；分母不可用或为 0 时显示 `—`，不除零。
- 净销售额优先使用订单利润 API 的净销售额字段；缺失时按销售额 - 促销折扣 - 退款金额计算。
- 毛利润 = 净销售额 - 商品成本支出中的销售成本净额（采购成本扣除可计算的不可售退货成本，再加头程成本）。
- 净毛利率按领星订单利润的利润链和自定义费用计算；任一必要实际字段缺失时显示 `—`，不得用模拟值替代。旧的内部利润链只用于兼容历史字段，不会作为表格展示科目。

### 3.2 预算目标联动

预算值复用现有 `budgetTargetService` 已解析的月度预算，不复制、不重建预算数据。月报对每一个选择月份、店铺和国家读取相同的预算记录并累计，因此预算目标页成功更新后，下一次月报查询必须读取更新后的解析结果；月报不得使用旧预算缓存。

现有预算模型可提供的预算科目及其月报归属为：

| 预算字段 | 月报科目 |
| --- | --- |
| `salesTarget` | 销售收入净额 |
| `adBudget` | 推广费用 |
| `refundTarget` | 退款金额 |
| `profitTarget` | 销售利润 |

没有上述预算字段的实际科目，其“预算值”和“达成率”显示 `—`；不得从实际值反推预算，也不得把某一总预算任意摊入其他费用科目。

“查看预算目标”将当前月份、店铺、国家带入预算目标页，供用户核对或上传对应预算；预算目标页也应能接受并显示这些联动筛选。若某个选择范围没有匹配预算，月报明确标注“未配置预算”，并给出该入口。

`达成率 = 实际完成值 ÷ 预算值`。预算为 0 或不存在时显示 `—`，不显示误导性的 0% 或 100%。费用科目的达成率同时呈现“实际 / 预算”数值，避免只以高低颜色判断好坏。

### 3.3 货币

- 有效店铺范围涉及多个国家时，表格以人民币（CNY）汇总。
- 有效范围只涉及一个国家时，按订单利润 API 返回的原币币种分别展示；同一国家的不同币种不能直接相加。
- 多国人民币汇总时，实际值优先使用领星订单利润返回的人民币金额；若 API 只返回原币和汇率，则用该 API 返回的汇率换算。预算目标使用同一店铺/国家/月的领星汇率换算为人民币，以确保实际与预算的分子分母处于同一币种。
- 任一参与汇总的实际或预算记录缺少领星可追溯的人民币金额/汇率时，相关金额不能参与人民币总和，必须显示缺失原因；不得猜测、硬编码或偷偷使用另一来源汇率。
- 页面 banner、表头和导出文件均明确标记“人民币汇总”或“原币分币种”。

## 4. 架构与文件归属

| 层级 | 所有者与职责 |
| --- | --- |
| 视图 | `index.html` 新增财务导航项与月报页面骨架；不把业务渲染写入 HTML 内联脚本。 |
| 前端特性 | `assets/js/features/store-operating-monthly-report.js` 拥有筛选状态、自动月份刷新、加载、表格/状态渲染、导出和预算目标深链。 |
| 共享前端 | 复用 `filter-controls.js`、`data-table-manager.js`、格式化和下载工具；不在 `app.js` 新增特性状态机、渲染器或事件绑定。 |
| 路由 | `server.js` 只装配路由、认证和财务权限校验；不承载科目或币种规则。 |
| 适配器 | 现有领星适配器负责订单利润请求及原始字段规范化。 |
| 业务服务 | `src/services/storeOperatingMonthlyReportService.js` 校验筛选、拆分月区间、组合实际/预算、决定币种模式并返回数据状态。 |
| 映射 | `src/services/storeOperatingMonthlyReportMapper.js` 是订单利润字段到月报科目的唯一翻译位置。 |
| 预算 | 继续由 `src/services/budgetTargetService.js` 读取已解析预算；仅按需增加可复用的筛选/失效能力。 |
| 样式 | 新增 `assets/css/pages/` 中的页面源文件，复用 `design.md` token 和共享筛选、面板、表格规则；运行 `npm run build:css`，不手改 `styles.css`。 |

不修改现有平台回款、应付账款、销售看板、订单利润适配器之外的无关业务逻辑；不为普通业务列添加页面级固定宽度或 `min-width` 补丁。

建议 API 边界：

- `GET /api/finance/store-operating-monthly-report`：接收开始月、结束月、店铺、国家和 `currencyCode`（默认 `CNY`），返回矩阵、币种/来源元数据、预算状态和生成时间。
- `GET /api/finance/store-operating-monthly-report/export`：只接收与页面相同筛选（包括 `currencyCode`），调用同一服务生成导出内容；不接受前端提交的金额。

## 5. 错误、可观测性与验收

数据源失败必须返回可诊断错误，不能伪装成空表或旧数据。页面分开呈现加载中、无匹配数据、预算缺失、部分科目不可用和请求失败，并给出数据源、范围和缺失字段/科目摘要。

服务日志记录请求 ID、月份范围、店铺/国家筛选数量、有效范围的国家数、币种模式、订单利润记录数、预算匹配数、未映射科目、缺失汇率数量、缓存状态和耗时；不得记录令牌、密码、完整订单明细或预算原文件内容。

自动化测试至少覆盖：

1. 月份顺序、最大 12 个月和左闭右开领星请求边界；
2. 店铺/国家交集、空筛选的全量范围及无匹配范围；
3. 跨月实际/预算累计、四个已定义预算科目以及未配置预算的 `—`；
4. 单国原币分组、多国人民币汇总、预算人民币换算和缺失汇率的显式失败；
5. 销售收入净额为 0、预算为 0、订单利润字段缺失、未映射科目和上游错误传播；
6. 预算更新后的月报重新读取和带筛选的预算目标深链。

浏览器验收覆盖：目标页无控制台错误；月份选择自动刷新；店铺/国家多选可鼠标和键盘操作；无效日期范围不会请求；桌面和窄视口无文字重叠且仅表格横向滚动；请求包含正确筛选；导出内容、币种标记、关键行和数据状态与页面一致。
