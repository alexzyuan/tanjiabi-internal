# 法定发件主体品牌规则设计

## 决策

法定发件主体不再维护逐店铺审批映射。运行时领星店铺名称只要包含已确认的品牌标识，即按品牌解析唯一法人主体：

- 名称包含 `tandanbo`（忽略大小写）时，使用厦门坦蛋伯网络科技有限公司。
- 否则名称包含 `tanjia`（忽略大小写）时，使用厦门探嘉网络科技有限公司；`xiamentanjia`、`tanjia-eu-DE`、`tanjia-eu-UK` 均属于此规则。
- 物流历史记录若只保留中文展示名，则“坦蛋伯”和“探嘉”作为上述两个品牌标识的兼容形式；它们不参与运行时店铺目录筛选。
- 两个标识均未命中时保持失败，不根据国家、站点或 SID 推断法人主体。

`tandanbo` 规则先于 `tanjia` 检查，避免未来名称组合产生错误归属。法人名称、统一社会信用代码、联系人和中英文地址继续由 `src/data/fbaAddressBook.js` 的两个 profile 统一提供，并允许现有 `.env` 字段覆盖。

## 运行时边界

品牌规则只决定法人归属，不创建店铺。店铺必须先存在于领星 seller API 或其真实缓存，才允许出现在 FBA 店铺列表、候选货件、STA 和 Jiufang 流程中。静态目录和名称规则都不得在运行时目录缺失时补出店铺。

物流请求携带 SID 时，服务端必须先用 SID 从运行时目录取得规范店铺名称；传入名称与规范名称或展示名冲突时应在生成物流 payload 前失败，不能用客户端名称覆盖运行时身份。

## 失败与验证

未知品牌店铺继续进入 `unmappedShops`，物流 payload 生成前必须失败。测试覆盖：

- `tanjia-eu-DE`、`tanjia-eu-UK` 和大小写变体解析为探嘉主体；
- `tandanbo` 名称解析为坦蛋伯主体；
- 未知名称仍失败；
- 运行时目录中的区域探嘉店铺可进入 `/api/fba/shops` 并生成带探嘉法人信息的九方模板。
